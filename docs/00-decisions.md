# Decisions log

Deviations from / resolutions of `Coconnect— Labour Marketplace Full Implementation Plan.md`.
Newest at the bottom. Every future session reads this first.

| # | Date | Decision | Why |
|---|------|----------|-----|
| 1 | 2026-10-29 | **Multiple awards per job.** `awards` has no `unique(job_id)`; `unique(bid_id)` instead. | Owner answered open question 2: a 20-worker job may be filled by several brokers. |
| 2 | 2026-10-29 | Hiring closes automatically once awarded `workers_count` ≥ `jobs.workers_needed` (or on the first award if `workers_needed` is null). Publisher can also `close_hiring()` early. | Keeps single-award behaviour for simple jobs, supports crews for large ones. |
| 3 | 2026-10-29 | Closing hiring moves the job straight to `in_progress` (the `awarded` enum value is unused). Contacts are revealed per award, immediately on `award_bid`. | Plan's MVP scope says "On award … the job moves to in_progress". |
| 4 | 2026-10-29 | Cancelling an award when hiring had closed reopens the job (`published`) and restores bids that were auto-rejected by the close (`bids.auto_rejected`). | Plan: "job returns to published with its remaining bids intact". |
| 5 | 2026-10-29 | Completion is per award. Job becomes `completed` when hiring is closed and every active award is completed. Reviews are unique per `(job, reviewer, reviewee)` and gated by a completed award between the two. | A publisher with three brokers rates each one. |
| 6 | 2026-10-29 | `bids.total_amount` respects the rate unit: `per_worker_per_day` = rate × workers × days, `per_day` = rate × days, `per_project` = rate. | The plan's formula multiplied per-project rates by workers and days. |
| 7 | 2026-10-29 | `public_profiles` is a definer view (NOT `security_invoker`). | With `security_invoker` plus the own-row-only policy on `profiles`, the view would only ever return the caller's own row. The view has no phone column, so this is safe. |
| 8 | 2026-10-29 | All state transitions are SECURITY DEFINER RPCs; `authenticated` has **no** INSERT/UPDATE grant on `bids`, `awards`, `payments`, `user_roles`, or `jobs.status`. Column-level grants restrict what `jobs`/`profiles` updates may touch. | Rule 3: the database decides. The mobile app gets identical rules. |
| 9 | 2026-10-29 | Deny-by-default privileges: `public` schema objects get no automatic grants to anon/authenticated; PUBLIC EXECUTE on functions is revoked globally (migration 0006). | Supabase's defaults would expose internal helpers like `notify()`. |
| 10 | 2026-10-29 | Job `lat`/`lng` are rounded to 2 decimals (~1 km) by trigger. | Public display must be coarse; storing coarse values means they cannot leak. |
| 11 | 2026-10-29 | Phone verification: users may save a number (unverified) directly; Supabase Auth OTP (`updateUser({phone})` + `verifyOtp('phone_change')`) marks it verified via a trigger on `auth.users`. Setting `require_phone_verification` (default false) gates bidding/posting on verification once SMS is configured. A phone (verified or not) is always required to post or bid. | No SMS provider is configured yet; the marketplace must still work in dev. |
| 12 | 2026-10-29 | `notifications` doubles as the email outbox (`emailed_at`). DB functions insert notifications; the app's dispatcher sends emails. | Cron-generated events (expiry, auto-confirm) get email too, with one code path. |
| 13 | 2026-10-29 | Scheduled work (expiry, expiry warnings, 7-day auto-confirm, rate-limit pruning) runs in **pg_cron** inside the database. | No Vercel cron needed; works for the mobile app too. |
| 14 | 2026-10-29 | `cacheComponents` is OFF in `next.config.ts`. | Nearly every route reads the auth cookie; Cache Components would require Suspense + `use cache: private` everywhere for little gain at this scale. Revisit for the homepage in M13 if Lighthouse needs it. |
| 15 | 2026-10-29 | Forms use React 19 `useActionState` + server actions + shared Zod schemas; React Hook Form is not used. | Smaller client JS for slow phones; progressive enhancement. |
| 16 | 2026-10-29 | ~~Tamil stubbed~~ → superseded by 27: Tamil is complete. | — |
| 17 | 2026-10-29 | Migrations are applied to the hosted Supabase project with `npm run db:push` (records in `supabase_migrations.schema_migrations`, CLI-compatible). No local Docker stack. | Owner's choice. |
| 18 | 2026-10-29 | UI primitives are hand-written shadcn-style components in `src/components/ui` (no shadcn CLI). | Same copy-in model; avoids CLI friction with Tailwind v4 via the Turbopack loader. |
| 19 | 2026-10-29 | Homepage "district map" is a **tile cartogram** (25 tiles in approximate geographic position) instead of traced district boundaries. | No accurate boundary paths were available; a stylised cartogram is honest, tiny, and tappable. Swap in real SVG paths later if wanted. |
| 20 | 2026-10-29 | Emails are sent via Resend's HTTP API (no SDK). Without `RESEND_API_KEY` they are logged as dry-runs. `/api/cron/dispatch` (Vercel Cron, `CRON_SECRET`) flushes emails for cron-created notifications. | Fewer dependencies; works in dev without a key. |
| 21 | 2026-10-29 | Admin/moderator UI strings are translated (en + si) like the rest of the app. Legal pages are a clearly-marked **draft for legal review**. | Rule 4; PDPA compliance needs a lawyer, not generated text. |
| 22 | 2026-10-29 | Map pin on job pages is a link to OpenStreetMap at the (already ~1 km-rounded) coordinates, not an embedded map. | No mapping JS on slow phones; never a precise pin. |
| 23 | 2026-10-29 | **Public data is cached across visitors** with `unstable_cache`, read through a *cookieless anon client* (`src/lib/supabase/public.ts`): districts, cities, active categories, public settings, homepage stats, recent jobs, ad candidates. Tags in `TAGS`; admin actions call `updateTag`, awards/cancel call `revalidateTag(…, "max")`; otherwise 60 s (jobs/stats), 5 min (settings), 1 h (categories), 1 day (districts). | Homepage TTFB went from ~700 ms to ~35 ms. The anon client can only ever see what RLS gives `anon`, so a shared cache cannot leak user data (e2e checks this). Search results and anything per-user stay uncached. |
| 24 | 2026-10-29 | **Fonts are self-hosted with `next/font/local`** (`src/fonts/`): one variable woff2 per script with Google's unicode-range. The language switcher uses `font-ui` (Latin + system fallback). | `next/font/google` emits every subset; the ZWJ in Sinhala conjuncts matched the Devanagari/Latin ranges and pulled ~130 KB of unused fonts; the switcher's native-script labels made English pages download the Sinhala and Tamil fonts (~180 KB). |
| 25 | 2026-10-29 | **Sentry**: server via `src/instrumentation.ts` (`@sentry/nextjs`, `onRequestError`, no cookies/bodies/auth headers); browser via Sentry's **Loader Script** (`components/layout/sentry-loader.tsx`), which loads the SDK only when an error happens; React error boundaries call `reportClientError`. Both off until `SENTRY_DSN` / `NEXT_PUBLIC_SENTRY_DSN` are set. | Full browser SDK would add ~30–60 KB gzip to every page against a 200 KB budget. |
| 26 | 2026-10-29 | **hCaptcha** (`components/forms/captcha.tsx`), shown only when `NEXT_PUBLIC_HCAPTCHA_SITEKEY` is set. Sign-up/login/reset pass the token to Supabase Auth (which verifies it when Bot Protection is on). Phone-code sending (now a server action, `sendPhoneCode`) and job submission are verified by the app with `HCAPTCHA_SECRET`. | Supabase only protects its own auth endpoints; `updateUser({phone})` and job submission aren't covered. Tokens are single-use, so each token is verified in exactly one place. |
| 27 | 2026-10-29 | **Tamil is complete** (`ta.json` has every key). `npm run i18n:check` now fails on any missing key in si/ta and on any `{placeholder}` that differs from English. | Owner asked to complete everything; still needs native-speaker proofreading before launch. |
| 28 | 2026-10-29 | Performance measured with Lighthouse 12.8 mobile (simulated slow 4G, 4× CPU) against `next start` locally: `/en` 96, `/si` 91, `/ta` 92, `/en/jobs` 95, `/si/jobs` 91, `/ta/jobs` 93; accessibility/best-practices/SEO 100 on all. Homepage JS ≈ 176 KB gzip for modern browsers (the 38 KB polyfill chunk is `noModule`). `clay` darkened to `#a35a27` for 4.5:1 contrast. | M13 "done when": Lighthouse mobile ≥ 90. Re-measure on the production domain. |
| 29 | 2026-10-29 | Phone-width (360 px) fixes: `buttonVariants()` now runs through tailwind-merge (a passed `hidden sm:inline-flex` used to lose to the base `inline-flex`, so the header overflowed on every locale); `body { overflow-wrap: break-word }`; the language switcher shows only the native name; bottom-bar labels may wrap; hero `h1` is `text-2xl` on phones; two Tamil strings shortened (`nav.postJob`, `home.hero.title`) so they don't break mid-word. | Plan: built for low-end Android phones; Sinhala/Tamil words are much wider than English. |
| 30 | 2026-10-30 | Vercel Cron for `/api/cron/dispatch` is **daily** (`30 2 * * *`, 08:00 Sri Lanka) instead of hourly. | Vercel Hobby rejects crons that run more than once a day. Only emails for pg_cron-created notifications wait; in-app notifications and the pg_cron jobs are unaffected, and user actions flush emails too. Go back to hourly on Pro. |
